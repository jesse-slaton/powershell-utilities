# PowerShell 7 migration inventory

Every tracked `.ps1` and `.psm1` under `Scripts/` and `Modules/` (146 files), with what it needs to run on
PowerShell 7.x on Windows and a decision for each. Archived scripts ([ARCHIVED.md](./ARCHIVED.md)) are not
listed. Direction: every script worth keeping moves to PowerShell 7.x; the rest are retired. Tracking issue: #124.

## Method

1. **PSScriptAnalyzer.** Each file was run, one at a time (PSScriptAnalyzer is not thread-safe under
   `ForEach-Object -Parallel`), through the compatibility rules in
   [PSScriptAnalyzerSettings.psd1](./PSScriptAnalyzerSettings.psd1) after `. ./Tests/Install-TestDependencies.ps1`:

   ```powershell
   Invoke-ScriptAnalyzer -Path <file> -Settings ./PSScriptAnalyzerSettings.psd1 `
       -IncludeRule PSUseCompatibleSyntax, PSUseCompatibleCommands, PSUseCompatibleTypes
   ```

   Only findings against the PowerShell 7.0 profile (`win-8_x64_10.0.17763.0_7.0.0_x64_3.1.2_core`) are
   recorded here. The profiles do not resolve parameter abbreviations (`-Class`, `-f`, `-a`) or provider
   dynamic parameters (`Set-ItemProperty -Type`), so those hits are marked as false positives.
2. **Manual read.** Every file was read for 5.1-only constructs the rules miss: the WMI cmdlets and the
   `[wmi]`/`[wmiclass]`/`[wmisearcher]` accelerators, other cmdlets removed in 7 (`Get-EventLog`,
   `Test-ComputerSecureChannel`, `*-ComputerRestore`, `Add-Computer`), PSSnapins, workflows,
   `-Encoding Byte` and encoding defaults where the bytes matter, `Send-MailMessage`,
   `Invoke-WebRequest` HTML parsing (`ParsedHtml`), `String.Split(string)` (splits on the whole string
   on .NET, on each character on .NET Framework), .NET Framework-only types, hard-coded
   `powershell.exe` relaunches, and modules that load only through the Windows PowerShell compatibility
   layer.

Not findings (these work on 7.x on Windows): CIM cmdlets, COM through `New-Object -ComObject`, WinForms
and WPF, the registry provider, the ActiveDirectory module, and `Add-Type` of C# that uses only base
class library types.

## Decisions

- **keep** - compatible with PowerShell 7.x as is. A pre-existing bug noted in Findings is not a 7.x
  blocker; it is fixed with the unit tests for that directory.
- **port S / M / L** - needs changes before it runs correctly on PowerShell 7.x. S: a few mechanical swaps
  (under about 30 changed lines). M: several constructs or some logic rework. L: a large rewrite.
- **port via #NN / retire via #NN** - the file moves into that open module issue, which owns any change
  to it (7.x fixes and the bugs recorded here) or its retirement; the findings are recorded here for that
  work. A port via row can need no 7.x change at all.
- **retire** - moved to the archive per [ARCHIVED.md](./ARCHIVED.md), for one reason: obsolete product,
  one-time migration, superseded, org-specific, or broken/incomplete.
- **see #NN** - decided in another issue.
- **replaced by \<module\> (#NN)** - the module issue removed the script; a function in that module does its job.

Keep means the script is compatible with PowerShell 7, not that it already runs under 7 in production.
For the `-Sensor` and `-Package` scripts the deployment tool chooses the host (`powershell.exe` by
default), and switching that host to `pwsh` is a deployment change outside this repository.

Retirement moves and ports happen in follow-up issues; no script is changed by this inventory.
